# WP-R4 — `scbridge-ffi` C-ABI library

**Agent:** Codex. **Depends on:** WP-R1 (`Session`, in-memory decomposed export),
WP-R3 (`clip_catalogue`). **Build lock:** required.

## Goal
`libscbridge.so` + `scbridge.h` so the Unreal plugin can search entities and pull an
in-memory decomposed package without any intermediate files.

## Deliverables
- `crates/scbridge-ffi` (`crate-type = ["cdylib"]`), header generated by `cbindgen`
  into `crates/scbridge-ffi/include/scbridge.h` (checked in; CI diff-checks it).
- API (see `docs/03-unreal-export-design.md` §FFI): `sc_open` (p4k path or NULL,
  cache dir or NULL), `sc_cache_stats`, `sc_cache_evict(cap)`, `sc_search_entities`,
  `sc_clip_catalogue`, `sc_export_decomposed_mem`, `sc_last_error`, `sc_free_string`,
  `sc_free_blob`, `sc_close`, `sc_lights`, `sc_default_options`. `sc_options` is a `#[repr(C)]` struct with LOD, mip,
  material mode, attachments, interior, lights, shields, animations, default pose.
  Status codes as an enum; the last error message per handle.
- The in-memory package is an **uncompressed tar** with the exact on-disk layout of
  `scviewer decomposed` (so `tar -x` of the blob == the folder). Entries ordered:
  `Packages/**/scene.json` first, then all other entries sorted alphabetically
  (Data/ before Packages/ sidecars).
- Every entry point wrapped in `catch_unwind`; no Rust panic crosses the boundary;
  no allocation crosses without its matching `sc_free_*`. Progress callback
  (`phase`, `done`, `total`) may fire from rayon threads — say so in the header.
- `scripts/build_ffi.sh`: builds release `.so`, copies it + header to
  `ue/Plugins/SCBridge/Source/ThirdParty/SCBridgeLib/{lib/Linux,include}/`.
- `crates/scbridge-ffi/ctest/`: a 100-line C program linked against the `.so` that
  opens the archive, searches "gladius", exports it and writes the tar; run as an explicit shell step against prebuilt
  artifacts, separate from `cargo test`, with no nested Cargo builds. It skips
  when archive discovery fails and removes work files unless SCBRIDGE_CTEST_KEEP=1.

## Done criteria
- `nm -D target/release/libscbridge.so | grep ' T '` shows only `sc_*` symbols.
- C test writes a tar that extracts to a folder passing upstream
  `validate_decomposed_export` (via `scviewer validate <dir>`, add to the CLI if
  missing).
- A forced panic (test hook) returns `SC_STATUS_PANIC` with a message, no abort.
- Export of Gladius through FFI within 10 % of the CLI's wall time.

## Initial implementation / verification handoff (2026-11-09; historical)

Implemented the opaque-handle C ABI, generated header, Linux external UE module,
release staging script, C consumer, Rust boundary tests and header drift test.
All entry points contain unwinding Rust panics. Handles require serialized access;
progress may arrive on worker/rayon threads and finishes before export returns.
JSON and tar allocations have matching library frees. Open errors use thread-local
storage; other errors are per handle. A panic poisons the handle until close.

The generated ABI includes `sc_lights`, `sc_cache_stats`, `sc_cache_evict`, and
`sc_default_options`. `sc_options` is 40 bytes: ten uint32 fields (`lod`, `mip`,
`material_mode`, `attachments`, `interior`, `lights`, `shields`, `animations`,
`default_pose`, `collision_reserved`). Status codes are OK=0, INVALID_ARGUMENT=1,
ERROR=2, PANIC=3, UNSUPPORTED=4, CANCELLED=5. Material modes are textures=0, colors=1, none=2.
The test-only panic hook is absent from the deployment library.

Scope/contract notes:

- The supplied core has no public cache statistics method. The FFI reads its
  atomically published manifest as a read-only size/count snapshot and combines
  that with `Session::cache_status()` and the public default write cap. Eviction
  stays in `Session::cache_evict`; the requested cap applies to that call only.
- `animations=0` is now honored through core `include_animations` and CLI
  `--no-animations`; the option participates in cache format v9 package keys.
  The reserved collision field must be zero. No option is silently ignored.
- Tar bytes are returned untouched. Core order is scene.json first, then all
  other paths lexicographically (including Data before remaining Packages
  sidecars), rather than the older brief's sidecars-before-Data wording.
- Independent uncached exports differ in exactly one file:
  `Data/UI/Generated/.export_stamp.json`. Upstream `insert_ui_export_stamp` in
  `vendor/StarBreaker/crates/starbreaker-3d/src/decomposed.rs` writes wall-clock
  export time and the invoking executable's mtime. All other 501 files were
  byte-identical. The C integration test checks exact tar parity through the
  same core package cache; the benchmark also checks independent exports,
  allowing only the two timestamp fields to differ. No tar normalization occurs.
- The root workspace had no release profile; added thin LTO and stripping to
  match the vendored release profile, with explicit `panic = "unwind"`.
- Per assignment, no branch/commit, vendored edit, CLI edit or UE build was made.
  Only the assigned ThirdParty directory was touched under ue/. Its `.so` and
  all target artifacts are ignored; the header and Build.cs are source files.

## Authorized cancellation and animation switch (2026-11-09)

Implemented the narrow core/exporter changes authorized after review:

- `CancelToken` is a cloneable one-way `Arc<AtomicBool>`. All three entity export
  entry points and their cached companions accept a final `Option<&CancelToken>`.
  Cancellation is distinguishable as `scviewer_core::Error::Cancelled` through
  the existing anyhow result's `downcast_ref`; it is not a panic or string match.
- Core checkpoints run before assembly, before tar construction and immediately
  before cache publication. An opt-in `Progress::with_callback` plus
  `report_checked` adds synchronous stoppable phase reports in upstream GLB
  assembly, GLB packing and decomposed writing on branch `scviewer/lights`.
  Existing polling/report APIs remain available; ordinary Progress callers never
  request cancellation. No asset-specific rules were added.
- The publication checkpoint is the commit point. After it, cache publication
  and folder unpack complete without another cancellation check/callback. Thus
  Cancelled cannot leave a new package cache entry or partial output folder;
  existing entries/files are preserved. Cancellation is cooperative and cannot
  interrupt an individual long-running decoder. A late request after the commit
  point does not turn a successful publication into Cancelled.
- ABI v2 makes `sc_progress_cb` return int: zero continues, nonzero cancels.
  `SC_STATUS_CANCELLED = 5` returns an empty blob without poisoning the handle.
  The host must serialize every handle call. Its busy-handle lock blocks close,
  last_error and search until export returns or is cancelled; callbacks must not
  reenter that handle. The library does not introduce an internal host lock.
- `GlbOptions::include_animations` defaults to true and is passed upstream.
  `sc_options.animations=0` and CLI `--no-animations` now disable clip/sidecar
  output. Serialized package options contain this flag; cache format is v9.
  `collision_reserved` remains required to be zero.

Tests were added before implementation: the new core tests initially failed to
compile against the missing token, option field and export arguments. They now
exercise cross-thread token sharing, cancellation at preparation, first assembly
phase, root-asset writing, tar build and publication; cache/output preservation;
pre-cancelled GLB/cache-hit exports; successful animation-disabled exports,
separate animation-on/off cache keys, and cache reuse. The C test cancels on
callback two, checks status 5/empty blob/unchanged cache size and count, and then
searches successfully on the same handle. The C script also compares and validates
both animation-enabled and disabled packages against the CLI. Counts remain
informational, following the review fixes.
